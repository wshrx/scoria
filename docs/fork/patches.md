# Fork patches and upstream sync

Scoria is Horizon's engine plus a Scoria launcher and UI. The smaller the engine diff, the cheaper
every upstream update. This file is the list to keep honest.

Base: `b53cfcd14` (upstream `main`, 2026-11-02). Scoria `dev` is **9 770 commits behind** and
163 commits ahead. The engine patch series is small; the drift is not. `tools/check_upstream_patches.sh`
currently fails on `0001-fix-input…`: upstream moved the text-field code and renamed
`game/native_panel.rs` to `game/mod_browser.rs`.

## Engine (`crates/`) — 7 patches

The series in `docs/fork/engine-patches/`:

1. **Non-Latin typing** — `typed_text()` / `typed_character()` use `KeyEvent.text`, then fall back
   to `logical_key`; chat, books, command blocks, LAN screen, mod browser, recipe book, sign edit
   and startup menu pass the result through. Test: `cargo test -p horizon-client --bin
   horizon-client cyrillic`. Upstreamable: yes.
2. **Scoria icons** — brand assets and the upstream-check automation.
3. **Motion cube** — the chosen mark everywhere, generated by `make_icons.sh`.
4. **Release key** — the Scoria Ed25519 key in `crates/horizon-release-sign/release-keys.txt`.
5. **Online-mode wording** — the disconnect text names Scoria and points to offline/LAN.
6. **Microsoft surface I** — no `--check-accounts`, offline-only server docs.
7. **Microsoft surface II** — no `--session-file` / `HORIZON_SESSION_FILE`; online mode is refused.

Nothing else in `crates/` differs from upstream. Do not rename crates, reformat upstream files or
move modules: those turn every merge into a conflict.

## Launcher (`launcher/`, `launcher/ui/`, `launcher/ui-kit/`, `launcher/xtask/`)

This is the real fork and the source of most conflicts:

- Microsoft accounts and sessions removed; offline names (Unicode) in `account.rs`.
- Telemetry removed (`telemetry.rs`, owner gate tests).
- piston-meta/piston-data download, retries, IPv4-first DNS (`piston.rs`, `mojang.rs`).
- Modrinth source and ported-mod install (`browser/`).
- JSON API: worlds keyed by folder + `lastPlayedAt`, `playing`/`playingPid`, `running.rs` lock.
- The window is `launcher/ui/` on gpui-ce with `launcher/ui-kit/`; `launcher/xtask/` orchestrates.
  Upstream's GPUI/Bun window must never replace them.

## One-time large sync (9 770 upstream commits)

Do it as one deliberate port, not a blind merge:

1. `git switch -c sync/upstream-YYYYMMDD upstream/main`
2. Merge `dev` into it. Resolve in this order:
   - `.github/`, `.githooks/`, `AGENTS.md`, docs: keep Scoria's content.
   - `crates/`: take upstream. Re-apply the 7-file/7-patch series afterwards, starting with the
     typed-text change (upstream moved `native_panel.rs` to `mod_browser.rs`), then run the
     Cyrillic test.
   - `launcher/`: keep Scoria's offline/piston/Modrinth behaviour and the gpui-ce UI; port
     upstream launcher fixes selectively.
3. Run `cargo test` in `launcher/`, the client Cyrillic test, and the UI gates.
4. Merge the sync branch into `dev`. Record the new base here.
5. Next sync is weekly; 9 770 is what happens when it waits.

## Engine patch queue

`docs/fork/engine-patches/*.patch` is a `git format-patch` series of every commit that touched `crates/`
(input, icons, release key, Microsoft removal). To rebuild the fork on a new upstream:

```sh
git switch -c sync/upstream-YYYYMMDD upstream/main
git am -3 docs/fork/engine-patches/*.patch     # resolve conflicts, keep order
sh tools/check_fork_surfaces.sh
```

The check fails if `typed_text`, the Scoria online-mode text, the offline-only server, the session
file removal, the release key or the icon disappear. It also runs at the start of
`tools/sync_upstream.sh`.

## What a sync may and may not touch

- **`crates/`** — upstream owns the code; our changes are the seven patches. Take upstream, re-apply.
- **`launcher/`, `launcher/ui-kit/`, `launcher/ui/`, `launcher/xtask/`** — ours. Never `git checkout
  upstream/main -- launcher`; that would replace the Rust UI with Horizon's and lose the offline
  launcher. `tools/check_fork_surfaces.sh` fails when the UI crates or the in-process API vanish.
- **Docs, packaging, release workflow** — ours.

Two checks guard this:

```sh
sh tools/check_fork_surfaces.sh      # after a sync: every Scoria surface is still there
sh tools/check_upstream_patches.sh   # before a sync: the patch series still applies
```

`sync_upstream.sh` runs the second before merging and the first after, so a sync that would lose a
fix stops instead of landing.

## Sync runbook

```sh
sh tools/sync_upstream.sh      # fetch, branch, merge, run the gates; never pushes
```

1. Run it weekly and before a release.
2. Resolve conflicts **in the sync branch**, never on `dev`.
3. If a conflict is in `crates/`, prefer upstream and re-apply our small patch on top.
4. If a conflict is in `launcher/`, keep our fork behaviour and re-run `cargo test`.
5. Merge the sync branch into `dev` only when all gates pass.
6. Record the new upstream commit here and in `PROJECT_STATE.md`.

## Rules

- Engine patches: one reason per patch, small, with a test, with an upstream PR if possible.
- No engine refactors, renames or formatting commits.
- Features that need deep engine changes: prefer a module/feature flag or an upstream PR over a
  long-lived fork.
- Launcher changes are free to diverge; UI changes cannot conflict.
